# RestockIQ: Flutter Frontend (APP) Development Guide

Welcome to the **Frontend Module** of RestockIQ! This document is the master roadmap specifically for the UI/UX developers on the team. 

Our goal is to build a cross-platform mobile app (using Flutter) targeted at **non-technical cafe and bakery owners**. The UI must be frictionless, hiding all the complex Prophet/XGBoost Machine Learning math behind simple, actionable screens.

---

## 🛠️ Tech Stack & Rules
*   **Framework:** Flutter (Dart)
*   **Target Devices:** iOS & Android (Mobile First)
*   **Backend Connection:** Will consume a FastAPI (Python) backend via REST.
*   **Golden Rule of the UI:** The user should never have to guess what a number means. The app tells them *exactly* what to do (e.g., "Order 15 Croissants") using plain-language explanations.

---

## 📱 Development Roadmap: The 7 Core Screens

This is the exact sequence in which the UI should be built. **Do not skip Item Setup (Screen 2)**, as the entire Machine Learning backend will crash if items are not defined first!

### 1. Login & Authentication Screen
*   **Function:** Standard email/password login (connected to Firebase Auth).
*   **Role-Based UI:** The app must support 2 roles (Owner vs. Manager/Employee).
*   *Requirement:* Only the Owner role can see the "Manage Staff" section in Settings.

### 2. Item Setup Screen (CRITICAL DEPENDENCY)
*   **Function:** A form to add/edit menu items.
*   **Critical Fields:** Item Name, Category, Price, and a **Perishable vs. Non-Perishable Toggle**.
*   *Why it matters:* If the UI does not capture whether an item is perishable, the backend ML Waste Action Engine cannot function.

### 3. The Main Dashboard (Home Screen)
*   **Function:** The first thing the owner sees in the morning.
*   **Components:**
    *   **LLM Daily Summary:** A card at the top displaying a plain-language summary generated by the AI (e.g., "Good morning! Expect high demand today due to rain. Order 15 extra coffees.").
    *   **Today's Restock List:** A simple checklist of items and exactly how many units to restock.
    *   **Cold-Start Badges:** If an item is new (less than 30 days of data), display a small badge next to it: *"Learning your patterns — Day 5/14"*.

### 4. End-of-Day Inventory Input Screen
*   **Function:** Where the staff logs what didn't sell at closing time.
*   **Smart Pre-fill:** The UI should automatically pre-fill the "Leftover" box with the system's calculated guess. The user only types if the system is wrong (manual override).
*   **Perishable Rule:** If an item is marked as Perishable, the leftover input box is locked and auto-resets to 0 (since it gets thrown away).

### 5. Item Detail & Forecast View
*   **Function:** When a user taps an item on the Dashboard, this screen slides up.
*   **Components:**
    *   **The Math Explained:** Show the restock formula visually: `[Predicted Demand] + [Safety Stock] - [Current Stock] = [Restock Qty]`.
    *   **Trend Graph:** A simple 7-day line chart showing Actual Sales vs. Predicted Sales.
    *   **Narrator Explanation:** A small text block where the LLM explains *why* the demand is high (e.g., "Demand is up 20% because tomorrow is a public holiday").

### 6. Waste Action Alerts
*   **Function:** Intraday alerts for slow-moving stock.
*   **Components:** High-visibility cards (or push notifications) that flag an item.
*   *Example UI:* "Warning: Croissants are selling very slowly. Action Recommended: Apply a 20% discount now to clear inventory." (Includes reasoning on tap).

### 7. Settings & Management
*   **Function:** Basic app management.
*   **Components:** Manage menu items, Notification toggles, and Staff Management (strictly locked to the Owner role).
